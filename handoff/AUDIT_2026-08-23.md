## CRITICAL — open

**C1. `data/records/*.json` has two concurrent writers and they can clobber each other.**
`catalogue_web --recatalogue` rewrites a record wholesale (marvel.json went 1,051 → 30,207
entries) while `pipeline.py` phases hold a record loaded at phase start and `write_record()`
their stale in-memory copy back whole. If entrypass reaches marvel while the re-catalogue has
already fattened it, the pipeline will silently revert it to the thin version. No error, no
log — the loss looks exactly like the file was never re-catalogued.
*Suggestion:* before every `write_record()`, re-read the file and merge only the fields the
phase actually changed (per-entry `category/scale_note/magnitude/topic/catalogued`, or the
`synthesis` block); alternatively a per-record lock file. Until then, do not run pipeline
phases 1–2 concurrently with a re-catalogue.

**C2. `data/CHAIN.json` is written in two different schemas.** `chain.py --main` writes
`{edges, names, strengths, identified, components, deviance_per_df}`; `pipeline.phase_chain`
writes `{edges, unmatched, fit}`. Any consumer breaks depending on which ran last.
*Suggestion:* one `chain.write_result()` used by both callers.

**C3. The catalogue remedy will re-dispatch into the IP ban.** `MIN_CATALOGUE_COVERAGE = 1.0`
plus `run_catalogue_gap` means the foreman restarts the catalogue every round while Fandom is
unreachable, each run burning its skip-list and extending the block.
*Suggestion:* a reachability gate — probe one fandom host cheaply; if the socket drops, the
remedy reports "network-blocked, deferred" instead of starting the job. (A `fandom reachable`
standard would also make the ban visible on the dashboard, which today it is not.)

## HIGH

**H1. The export repo lives in the session scratchpad.** `PANSCRIPTUM_EXPORT` points into
`...\Temp\claude\...\scratchpad\panscriptum-export` — a directory that dies with the session.
The published history survives on GitHub, but local state (the repo, its remote config) will
vanish and the publish loop will silently re-init somewhere else.
*Suggestion:* move to a stable path (e.g. `C:\Users\imarl\panscriptum-export`), set
`PANSCRIPTUM_EXPORT` at User scope, `git clone` from origin there.

**H2. `hostcheck.adopt()` mixes metrics in its best-candidate slot.** `best[0]` is seeded 0.0,
compared against `r["lift"]`, but assigned `r["rate"]` — so comparisons across candidates are
lift-vs-rate and the printout labels a rate as "lift". A worse-lift host can win.
*Suggestion:* track `(lift, rate, host, verdict)` and compare lift to lift.

**H3. `hostcheck.purge()` documents a two-condition safety rule it does not enforce.** The
docstring: roster must fail the audit AND the host must have been independently rejected. The
code purges whatever `--source` names; the `unfit` map is loaded and never read (pyflakes
flagged the dead local). Human-in-the-loop was the deliberate replacement — then say so and
delete the dead load, or enforce the second condition.

**H4. `pipeline.update_handoff()` publishes a stale phase table after every unit.** It
hardcodes phases 4–8 as "to build" (all are built), and "Sources catalogued {have}/215" (the
roll is 210). The module docstring's line 28 ("Phases 4-8 … not yet implemented") is equally
stale. *Suggestion:* derive the table from `IMPLEMENTED`, and the denominator from the roll.

**H5. `update_handoff()` re-parses every record after every completed unit.** With marvel.json
at 30k entries that is a full parse of ~86k entries per synthesis unit — the status file
becomes the heaviest thing in the phase. *Suggestion:* cache counts and refresh every N units.

**H6. A vacuous check in `verify_math.py` (§8):** "Ruin and Acumen carry identical bit-worth"
compares `R.measure_bit_value("M7") == R.measure_bit_value("M7")` — the same call twice. It can
never fail. *Suggestion:* assert the real claim (bit-worth is a function of band only, no
per-axis table exists) or delete it.

**H7. `config.yaml` comments contradict its values.** The `num_ctx` block narrates
"Raised 8192 → 12288" above `num_ctx: 6144`; the seed block says "temperature 0" above
`temperature: 0.2`. Whoever tunes from these comments inherits wrong facts.

**H8. `foreman.adopt_hosts` counts "0 adopted" as success.** It greps stdout for the substring
"adopted", and `adopt()` always prints "N adopted, M genuinely without a wiki".
*Suggestion:* match `^([1-9]\d*) adopted`.

**H9. `dashboard.jobs()` is coupled to two hardcoded log names** (`read_auto.log`,
`roll_auto.log`) and to the exact format strings in read.py/feats.py. A renamed logfile or a
reworded progress line silently blinds the Jobs panel, the standard that reads it, and the
foreman remedy keyed on it. *Suggestion:* single constants module for job log names; dashboard
imports it.

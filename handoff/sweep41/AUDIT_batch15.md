## Findings filed

**1. `WEAVE_ENTITY_INDEX_NO_STALENESS_CHECK`** (MAJOR, LOCAL) — id `e0f9da6e9466`
`weave.py`'s continuity/identity resolution and its resonance graph (which cosmography's X.7
propagation distances are read from) are computed entirely from `data/ENTITY_INDEX.json`, read
blind by `load_index()` (weave.py:85-87) with no staleness or completeness check anywhere.
`ENTITY_INDEX.json` is built by a separate, manually-invoked script (`weave_index.py --write`)
and is **never** regenerated by any of `pipeline.py`'s own phases — `phase_weave`
(pipeline.py:2498-2524) calls `weave.load_index()` directly. If the corpus grows after the index
was last built, the continuity graph is silently derived from a partial snapshot. Verified this
is a real gap, not merely unread: `weave_index.py`'s own write path (lines 471-483) states
outright that "neither file carries a build stamp the other could be checked against" — the
codebase already knows no build stamp exists on `ENTITY_INDEX.json`/`WEAVE_CANDIDATES.json`, and
nothing was ever added to fix it. Checked `dashboard.py`, `health.py`, `coverage.py` and
`standards.py` directly — none report an age or freshness figure for `ENTITY_INDEX.json`, unlike
`corpus_db.py`'s explicit "print a banner saying how far behind the index is" discipline for a
structurally similar derived index (CLAUDE.md quotes this as a deliberate house rule). Remedy:
stamp the two files with a generated_at time / the (file_count, max_mtime) records-signature
`weave_index.py` already computes for its own build cache, and have a consumer compare it against
the live `data/records/` signature and report the gap.

**2. `ASSAY_ATTESTATION_FLOOR_NO_MONOTONICITY_GUARD`** (MAJOR, LOCAL) — id `6d132aa1e8aa`
`assay.py` carries two parallel five-grade attestation tables that both encode "worse evidence →
wider published interval": `SIGMA_BY_ATTESTATION` (guarded — `_check_constants()`, run at
import, refuses to load unless the five sigmas are strictly increasing Instrumented < Witnessed <
Transcribed < Reconstructed < Disputed, and unless none exceeds the ceiling) and
`ATTESTATION_FLOOR` (assay.py:1296-1297, used by `interval_from_hands()` and re-exported verbatim
as `custodes._ATT_BASE` to derive `custodes.ATTESTATION_QUALITY` for all ten Custodes'
`evidential_part` terms). `ATTESTATION_FLOOR` has **no equivalent check anywhere** — confirmed by
reading `_check_constants()` in full (it only examines `SIGMA_BY_ATTESTATION`) and grepping
`verify_math.py` and `drill.py` for any ordering assertion over `ATTESTATION_FLOOR`'s five
values; none exists. `drill.py:7900-7916` exercises it only at its two endpoints (Instrumented vs
Disputed) plus the already-fixed recognised/unrecognised-grade case. A mid-table edit preserving
both endpoints — e.g. swapping Transcribed=0.20 and Reconstructed=0.40 — would pass every
existing check silently and publish a narrower interval for worse-attested readings on that pair
of grades: the exact "less knowledge, narrower bar" defect this file's own header names as the
worst direction the library can be wrong in (the same defect `_check_constants()` was written to
catch on the sigma side), quietly missing its twin on the floor side. Remedy: fold
`ATTESTATION_FLOOR` into `_check_constants()` (or a sibling check at the same import site)
asserting strict monotonicity across all five grades, mirroring the check immediately above it
in the source.

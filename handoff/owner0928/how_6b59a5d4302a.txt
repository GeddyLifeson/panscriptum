The first failing or raising re-read reproduces the breach. A mid-edit artefact holds every time on a settled tree; a flaky net is unlikely to hold three times running. The owner's 2026-09-08 ruling (order 71ae3fa7e55e, re-read on a settled tree, never consult the maintenance guard) is otherwise unchanged. A net that recovers still leaves the run BREACHED and non-zero, so it still files DRILL_BREACH, whose `seen` count tracks a recurring flake. Net: "a breached net that holds once and then fails again is NOT dropped from the halt" (r10).
2. drill._live_watch's live-path list is hand-kept. RULING: KEEP AS-IS. Deriving it (e.g. every file under state/ and data/) would widen what the live-state witness counts as an escape. Several ordinary paths inside a net (health.flush into state/failures.json among them) would then read as leaks, and a witness breach halts the library. A detection list that errs by being hand-kept is safer than one that manufactures halts. No code was changed.

A failed read-back says so, is noted, and falls back to memory. Net: "resync_roll's closing 'roll now' figure is read back from disk" (r11), which simulates a second writer landing a row inside the run's window.
